# Right-Sized Design System

Authority is defined exclusively in `SKILL.md`. Inspect existing patterns, brand material, and references before designing; this inspection sequence is not a priority ranking.

Create the smallest useful shared system. For a single screen, a compact direction and a few tokens may suffice. For a product, formalize decisions using `templates/design-system.md`.

Define relevant items:
- Product context, primary jobs, density, source responsibilities, brand constraints.
- Visual direction and defining composition/type/imagery anchors.
- Semantic colors and accessible pairings; typography roles and actual font availability.
- Spacing/sizing, grid, surface/border/radius/elevation, motion/layer rules where needed.
- Core components with purpose, variants, relevant states, content constraints, and keyboard behavior.
- Responsive region transformations, accessibility, anti-patterns, and fidelity limitations.

Reuse coherent project conventions. Extend them where approved targets require change. Do not generate speculative components, rename an entire token system unnecessarily, or leave irrelevant placeholder sections in delivered documentation.
Ensure brand expression appears in actual layout, typography, imagery, and interaction decisions, not only a palette. Validate representative screens before spreading a new system across the product.
